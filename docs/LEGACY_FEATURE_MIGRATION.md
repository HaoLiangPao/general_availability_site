## 初始化与数据边界

1. 为新基座建立独立 PostgreSQL 数据库，设置 `DATABASE_URL`、`DIRECT_URL`；执行 `npm run db:deploy`。
2. 设置 `ADMIN_EMAIL`、`HOST_TIMEZONE`、可选 `HOST_DISPLAY_NAME` 与 `LEGACY_CURRENCY`（默认 `usd`；旧站只显示 `$`，上线前须确认实际币种）。
3. 需要电子转账时设置 `ETRANSFER_RECIPIENT_EMAIL`；需要刷卡时设置 Stripe 密钥及 Webhook。执行 `npm run seed:legacy`。脚本只创建缺失的类型，不覆盖已有类型；若后来补上密钥，需在后台启用对应类型并核对收款说明。
4. 在 `/admin/settings` 连接 Google 日历；没有真实日历连接时不要接受真实预约。设置邮件提供商后验证审批申请、批准与拒绝邮件。
5. 此脚本迁移的是**功能和预约类型**，没有把旧数据库中的客户或历史预约复制到新数据库。历史数据须先确认来源、备份、是否仍有效及去重规则，再单独导入。

## 上线前特别核对

- 旧版只把付款选择与优惠显示写进备注，不能把旧预约视为“已经 Stripe 收款”。
- `ETRANSFER_RECIPIENT_EMAIL` 必须是真实已确认的收款地址；电子转账由主人线下核实，后台金额仅表示应收。
- 如果选择非 USD 币种，检查后台收入统计的展示币种；当前汇总沿用上游实现，按单一默认币种格式化。
- Preview 没有新版数据库、Google、邮件或 Stripe 密钥时，可以验证部署和静态说明页，不能验收真实预约或付款。
